# さつま町駅伝ライブ

第22回さつま町駅伝競走大会（2026年11月8日）で、8チームのタスキの位置と順位を地図にリアルタイムで出すためのページです。

| ページ | 使う人 | 中身 |
|---|---|---|
| `index.html` | 観戦する人（URLを配る） | 地図・順位・先頭との差・次の中継所までの残り距離と到着予想・区間表 |
| `runner.html` | タスキに付けるスマホ | GPSの位置をコース上の距離に直して送る。画面ロック・GPSログ保存つき |
| `setup.html` | 運営 | 8チーム分の送信機用QRコードと観戦ページのQRコードを印刷する |

Firebase の設定がまだのときは、観戦ページは**デモ表示**になります（8チームが架空のタイムで走ります）。

## しくみ

```
タスキのスマホ(runner.html) --5秒ごと--> Firebase Realtime Database <--5秒ごとに読む-- 観戦ページ(index.html)
```

- 送るデータは「最新の位置と距離」と「100mごとの通過時刻」だけです。先頭との差は、先頭チームがその地点を通った時刻と比べて出しています。
- 観戦ページは常時接続ではなく、数秒ごとに短く読みに行きます。Firebase の無料プランは同時接続が100件までなので、観戦者が数百人いても枠に収まるようにしています。
- 距離はコース線に沿って数えます。同じ道を2周するので、前回の位置より少し先の範囲だけを探して、別の周回と混同しないようにしています。

## Firebase の準備（30分くらい）

1. https://console.firebase.google.com で「プロジェクトを作成」します（無料の Spark プランで大丈夫です）。
2. 左メニュー「構築」→「Realtime Database」→「データベースを作成」を選びます。
   - ロケーションは**シンガポール（asia-southeast1）**にします。
   - 「ロックモードで開始」を選びます。
3. 「ルール」タブを次の内容に置き換えて「公開」します。誰でも読めますが、書き込めるのは鍵を持つ端末だけになります。
   ```json
   {
     "rules": {
       ".read": false,
       ".write": false,
       "live": { ".read": true }
     }
   }
   ```
4. 「データ」タブの上に出ている URL（`https://〜.firebasedatabase.app`）を、`js/config.js` の `firebaseUrl` に貼ります。
5. 送信用の鍵を取得します。歯車アイコン →「プロジェクトの設定」→「サービス アカウント」→「データベースのシークレット」→「表示」で出る文字列です。
   - **この鍵はファイルに書かないでください。** `setup.html` を開いたときに入力欄へ貼るだけにします。
   - 鍵が漏れたら、同じ画面でシークレットを削除して作り直し、QRコードを印刷し直してください。

## 公開

GitHub Pages などの静的ホスティングにこのフォルダを置くだけで動きます（サーバー側のプログラムはありません）。
位置情報は `https://` でないと使えないので、公開先は https にしてください。

## 当日までの流れ

1. **端末を8台そろえる。** 軽いスマホをタスキ用のポーチに入れます。小学生の区間もあるので、できるだけ軽い機種を選び、ポーチはタスキにしっかり留めます。
   - iPhone は「設定」→「画面表示と明るさ」→「自動ロック」を**なし**にしておきます（画面が消えるとGPSが止まるため）。
   - Android も画面の消灯時間を最長にしておきます。ページ側でも画面が消えないようにしています。
2. **QRコードを作る。** `setup.html` を開いて鍵を貼り、印刷します。
3. **試走する。** `setup.html` の「試走モード」にチェックを入れたQRで送信機を開き、コースを走るか、自転車や車で回ります。
   - 観戦ページに正しく出るか確認します。
   - 送信機の「GPSログ保存」でGPXを保存しておくと、コース線の精度を上げるのに使えます（下の「コース線について」）。
   - 試走が終わったら、Firebase コンソールの「データ」タブで `live` を削除して、試走のデータを消します。
4. **前日の夜**：端末を満充電にします。モバイルバッテリーも用意しておくと安心です。

## 当日

1. 9:30ごろ、各端末で（試走モードではない）QRを開き、「計測をはじめる」を押します。位置情報の許可を聞かれたら「許可」を選びます。
2. GPSが「良好」、送信が「OK」になったのを確認して「画面ロック」を押し、ポーチに入れます（ロックの解除は2秒長押し）。
3. 距離は **10:00 から**数えはじめます。それまでは位置だけが送られます。
4. 中継所ではタスキごと次の走者へ渡すので、端末の操作はいりません。
5. 観戦ページのURL（`setup.html` の最後のQR）を配ります。

## コース線について

`js/course.js` のコース線は、町が公開している大会コース図（PDF）から線を取り出し、国土地理院の地図に重ねて位置を合わせたものです。数十mくらいずれている可能性があります。

区間の距離表示は、区間表の公式距離に合わせて補正しています。走った位置を線上に重ねる処理は線から50m以内なら動くので、大会には十分使える精度のはずです。

試走のGPXで線を差し替えると、より正確になります。

- `tools/trace.html`：PDFのコース図を地図に重ねて確認する開発用ページ
- `tools/build-course.py`：`js/course.js` を作り直すスクリプト

## 手元での動作確認

```bash
python3 -m http.server 8780
python3 tools/mock-firebase.py 8781
```

- `http://localhost:8780/` を開くと、デモ表示になります。
- `http://localhost:8780/?db=http://localhost:8781` を開くと、テスト用サーバーに接続します。
- `http://localhost:8780/runner.html?team=blue&key=test&test=1&db=http://localhost:8781` を開くと、送信機をテストできます。テスト用サーバーの鍵は `test` です。
